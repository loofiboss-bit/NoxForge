# NoxForge 7.0.0 — Operational Precision

> **UNQUALIFIED DEVELOPMENT NOTES:** NoxForge 7.0.0 is not release-ready.
> The repository remains at `7.0.0-dev`; mandatory composed Wayland and
> input-capable qualification is pending. Local development artifacts must not
> be published or presented as release assets.

Operational Precision is a focused correction and consistency release for
Fedora KDE 44, Plasma/KWin 6.7+, Qt 6.11, and Wayland. It preserves the
Kinetic Precision identity while tightening window geometry, icon semantics,
native controls, shell spacing, session surfaces, diagnostics, and
reproducibility.

## Corrected behavior

- Aurorae maximized windows use the documented complete normal-frame fallback;
  incomplete special maximized center elements are no longer shipped.
- The NoxForge icon overlay inherits from Fedora's `breeze-dark`, `breeze`, and
  `hicolor` themes, with original distinct icons for the reported core and
  session actions.
- Native Qt controls respect KDE click and mnemonic policies, keep a full
  scrollbar hit target, and render a narrower visual thumb.
- Plasma surfaces use a consistent four-pixel rhythm and restrained nested
  borders without changing the established palette or brand.
- SDDM, Splash, Logout, and TabBox share scale-aware geometry, accessible
  feedback, distinct session actions, and explicit missing-icon behavior.
- Read-only diagnostics report complete active state, component provenance,
  unresolved critical icons, and KScreen/KWin per-output scale without using
  `QT_SCALE_FACTOR` as runtime proof.
- Sound checks preserve canonical sources across toolchains and require byte
  equality in the pinned FFmpeg 8.1.2 release environment.

## Qualification status and limitations

Static, unit, sanitizer, offscreen rendering, QML lint, deterministic archive,
Fedora development RPM/SRPM, isolated install-tree, repeated-install,
rollback, uninstall, configuration-preservation, and provenance checks are
part of the local gate. These checks do not qualify a composed desktop.

The complete 100/125/140/150/175/200 percent and mixed 100+140/100+200 output
matrix remains pending for maximized Aurorae, System Settings, Dolphin,
Konsole, panel/tray, popups, calendar, notifications, OSD, SDDM test mode,
Logout, and TabBox. Keyboard-only navigation, translation expansion, RTL,
disabled states, normal/reduced/disabled/slow motion, real SDDM authentication,
and power flows also require an authorized disposable environment. Pending P0
cases prevent a release-ready claim.

## Installation and upgrade

Only install a locally staged development RPM in a disposable Fedora 44 test
environment. Package installation must not apply the theme or change KDE,
KWin, panel, wallpaper, cursor, sound, or SDDM settings. Before testing an
upgrade from v6, record the active configuration and component provenance;
after upgrading, verify the RPM, run `noxforge-doctor --json`, and confirm that
the same settings remain active until the operator explicitly changes them.

## Rollback

Select a known-good Global Theme and SDDM theme before package removal. To
remove the package without dependency autoremove, use:

```bash
sudo dnf remove --no-autoremove noxforge
```

Then reinstall the qualified v6 package if rollback testing requires it.
Removal must delete only NoxForge-owned package paths and must preserve KDE and
SDDM configuration. No v7 development workflow may apply a theme, publish an
artifact, tag a commit, push a branch, or create a release.
